# Release Notes — v1.5.5 (2025-11-13)

## Highlights
- Dedicated snapshot directory management keeps backups on the disk you pick without editing env files.
- Snapshot/restore automation is more resilient: jobs stop containers cleanly, log their actions, and guard against concurrent work.
- UI/installer polish (settings layout, version badge, Waitress defaults, installer pins) keeps fresh deployments aligned with the release.

## Snapshot & Recovery
- Settings now exposes the snapshot directory, removing the need to poke `/etc` files when you want to target a different volume. The backend only enumerates the configured directory and trims stale warning copy from the dashboard.
- Snapshot creation stops the node container, flushes overlays, and refuses to start when another job is already running, preventing the deadlocks that previously wedged `_SNAPSHOT_JOB_STATE`.
- Automation logs capture every snapshot/restore (path, trigger, restart details). Deferred restores (when another job is running) generate entries so operators know why a recovery was skipped.

## Automation & Stability
- Liveness auto-recover is automatically suspended while snapshot or restore jobs are active so policy restarts can’t collide with maintenance.
- Snapshot status messaging was tightened to only report the active job’s progress instead of repeating location warnings, decluttering the dashboard.

## Dashboard & Settings
- Settings gained a dedicated Snapshot directory input plus refreshed login tiles. The footer badge reads `v1.5.5`, keeping the UI in sync with the shipped build.

## Installer & Runtime Defaults
- `install_nm_from_github.sh` and `install_node_manager.sh` now default to the `v1.5.5` tag so new installs under `/opt` land on this release automatically.
- `run_node_manager.sh` tunes Waitress to 12 worker threads, backlog 256, and unlimited connections for better responsiveness out of the box.

## Upgrade Notes
- Pull the tag: `git fetch --tags && git checkout v1.5.5`.
- Re-run `install_node_manager.sh` (or the remote installer) to sync `/opt/blockdag-node-manager`, then restart the service: `sudo systemctl restart blockdag-node-manager`.
